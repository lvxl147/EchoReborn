零、v7 首版的两个问题与最终处置

问题 1：Siri 图标模糊。v7 首版把 iOS 27 的 Siri 图标（588×497 源图）直接内嵌成 29pt 芯片。源图是位图、 且被压到 29×29pt（≈87px @3x），细节全部糊掉，观感反而不如原符号。 处置：废弃 PNG，回退到 v6 的粉色芯片 + 白色波形符号（#D4537E + i-wave）。 矢量符号在任意倍率下都锐利，这是位图做不到的。

问题 2：分类管理底色被我改错。v7 首版把橙底一起换成了浅灰底 —— 你要的只是换内部图标，不是换底色。 处置：底色保持橙色（#EF9F27），只把芯片内的字形从「文件夹」换成「三横线列表」。

净变更（相对 v6）：只有一行芯片的字形引用 <use href="#i-folder"/> → <use href="#i-list"/>， 其余页面结构、key、默认值、机制、执行顺序一个字都不变。

最容易写错的一处：原版 Soko 的 Root.plist 里 key 写的是 widgetOffset（不带前缀），前缀是它的 Swift 控制器在写入时补的 （setValue(v, forKey: "soko_" + key)）。改成纯 plist 直写后框架不再补前缀， 所以必须直接写 soko_widgetOffset。写成不带前缀会「滑杆能拖、锁屏没反应」—— 静默失效。
关于 Soko 要不要再加一个聚合总闸：本轮不加 —— Soko 原版就没有总开关，且你要求「各功能可自由开关」， 两个功能各自带开关已覆盖全部范围。若你希望它和 LiquidSiri 一样也有一个总闸，说一声，加一行 PSSwitchCell + 一个 early-return 即可。

五、实现机制

方案评估
A · 跨 bundle PSLinkCell
bundle=SokoPreferences
detail=SokoPreferences.RootListController		不采用。依赖另一个 PreferenceBundle 已 dlopen 且类可跨 bundle 解析；Echo Reborn 自己的注释里就记着这个坑。失败特征是「点了没反应」或整页空白。
B · 本 bundle 手推 plist 页
Soko.plist / Siri.plist
openSokoSettings: / openSiriSettings:		采用。与已上线的 openEnhancedSettings: 同一条路径：控制器手推 + 自己 loadSpecifiers(fromPlistName:)，不依赖跨 bundle 类解析。写值域与通知名指向对方项目。
C · 保持两个独立 PreferenceLoader 入口备选。改动最小，但做不到「在控制项下方」的版式。
选 B 后，两个项目的偏好域和 key 一个字都不改，两个 Tweak 的读取代码完全不受 UI 搬家影响 —— 换的只是「谁来画这一页」。 另外建议把 SokoPreferences.plist / liquidsiriprefs.plist 两个独立入口移除，否则同一功能会在「设置」根列表和 Echo Reborn 页各出现一次。
